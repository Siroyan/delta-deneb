# delta-deneb UIデモ

2026-10-12。ピットのメンバーが数値と走行位置を一目で把握できることを優先する。白を基調に速度・平均速度・周回・経過時間を大きく表示し、緑は接続状態と通常の走行状況に使用する。

## 一覧表示の配置

左右の余白を12pxとし、コンテンツの最大幅制限を外して画面幅を使う。幅600px以上では主要数値4項目を一列に表示し、左側はコース位置のみ、右側は速度グラフ・ラップ表・走行進捗を縦に並べる。ラップ時間はラップ表の上、距離・ゴール予測・目標との差は走行進捗にまとめる。600px未満ではスマートフォン向けの縦配置を使う。

ヘッダー・見出し・パネル間隔・ラップ表の行間を詰め、高さ850px以下のPC画面ではコース図とグラフをさらに調整する。文字やデータをクリップしたり、パネルごとに縦スクロールさせたりしない。戦略読み込み成功の補足は、常時表示の戦略名・ファイル情報と重複するため、コンパクト表示では読み上げ用に残す。読み込みエラーや通信状態の注意は画面に表示する。

地図は北を上、東を右に表示する。表示用アセットの回転を戻す座標変換を道路・ランドマーク・車両マーカー・戦略区間に共通で使用し、経路距離・GPS座標は変更しない。表示範囲は全コース点とランドマークの外接範囲に22単位の余白を加えて決める。現在位置のラベルは端に近いときに移動し、切れないようにする。北の方位マークを表示する。

926×1040pxのローカルプレビューで、北が上の大きなコース図・戦略サンプル・右側の3パネルがスクロールなしで収まることを確認した。戦略詳細・ラップ分析はユーザーが開く追加表示であり、開いた場合や小さい画面ではスクロールを許可する。

## ファイル構成

- `web/index.html`: 静的画面。
- `web/styles.css`: PC／タブレット／スマートフォン向けレイアウト。
- `web/app.js`: 自動更新、表示切り替え、ラップ分析、CSV保存。
- `web/js/mock-api.js`: 非同期の模擬データ取得とシナリオ。
- `web/js/format.js`: 欠測を含む値の表示、接続判定、参考値の算出。
- `web/js/charts.js`: SVGコース図、速度グラフ、戦略区間の背景。
- `web/js/strategy.js`: delta-vega schema 1の検証とGPSの経路投影。
- `web/js/strategy-ui.js`: ファイル選択、ブラウザ保存、戦略表示。
- `web/assets/course.json`: もてぎの表示・経路投影用データ。
- `web/assets/motegi_demo.json`: 読み込み確認用の戦略。

`web/`の内容をそのまま静的オリジンに配置する。現在はAWS CDKによる配信基盤と、DynamoDB・IoTルール・取得APIも別途実装している。画面はこの模擬データのままで、実APIへの接続はStep 3で行う。

## データの由来

MQTT項目はローカルのdelta-vega-v2の`lib/vega_core/src/application/telemetry_json.cpp`を参照した。確認済み項目は`speed`、`average_speed`、`lap_number`、`total_time_ms`、`lap_time_ms`、`latitude`、`longitude`、`timestamp_ms`、`machine_id`、`memo`。

模擬APIは中盤のLAP 4から始まり、時刻の経過とともに速度・距離・ラップを更新する。車両の実測値を表示するものではない。テスト用の目標は38:30、更新周期は3秒、更新停止判定は受信から10秒超。これらはデモ設定であり、実運用時に確定する。

`web/assets/course.json`は、delta-vega-v2の`assets/maps/motegi_oval_full/course.json`にある`segments`、`routes`、`landmarks`と座標変換から生成した。見やすい横向きの模式図へ回転・縮尺調整し、経路内距離・緯度経度を保持している。GPS由来の基準経路であり、測量済みのコース境界ではない。初周・中間周・最終周で経路長が異なる。

`web/assets/motegi_demo.json`はdelta-vega-v2の同名ファイルのコピー。ON/OFF地点は画面確認用の仮値で、実車制御や実戦の推奨地点ではない。

## 戦略との照合

ファイル上のON/OFF距離は各周の経路始点を0 mとする。全レースの通算距離や緯度経度として扱わない。

戦略読み込み時は入力全体を検証してから採用する。delta-vegaのパーサーと同様、未知・重複項目、別コース、欠周、区間の重なり、接する区間、範囲外の距離、指数表記、負数、4096バイト超を拒否する。識別子はASCII英数字・`_`・`-`・`.`。`plan_id`は39文字以内。`plan_type`は`demo`か`race`で、省略を認めるのは旧サンプル`dummy-race-001`だけ。

画面はGPSを当該周の基準経路へ投影し、その位置から次のON／OFF地点までの距離を推定する。GPS欠測または経路から60 m超では照合しない。速度グラフの区間背景は、サンプルのGPS位置を照合して描くため、境界にはサンプリング周期相当の幅がある。10秒超の欠測区間や周回境界をまたいで背景を連結しない。

実機エンジン状態や点火操作の成否は現行MQTTに含まれない。画面上の「使用予定」「惰性予定」は計画情報のみ。計画値を実測値と扱わない。

## 検証

Nodeの標準テストランナーで、走行の更新、更新停止からの復帰、GPS欠測、APIエラー、データなし、ゴール、長時間の更新間隔、リクエスト取消、戦略仕様、GPS投影を検証する。

ブラウザで模擬シナリオ、ラップ分析、グラフ範囲切り替え、実フォーマットのファイル選択、コース図とグラフへの重ね合わせ、別コースの拒否、既存戦略の保持、復元と解除を確認する。
